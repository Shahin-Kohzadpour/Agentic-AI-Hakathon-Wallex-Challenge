# Implementation briefs for Codex and Antigravity

These are handoff prompts, not instructions to start concurrent agents during planning. Inspect the repository and its instructions before choosing task ownership. Do not have two tools edit the same checkout simultaneously; use separate branches/worktrees if the team later chooses parallel work.

## Shared prompt: include in every implementation task

> Build for the supplied Wallex challenge and follow `planning/winning-plan.md`. Work only on the named scope. The allocated baseline is 5,000,000 TMN, pending account verification. The source exclusion list contains 345 exact pairs; use the full machine-readable set and verify its checksum. Never print, commit, embed in prompts, or copy the exchange credential into fixtures. Treat the original archive as credential-bearing too. Default to offline/replay or shadow mode. Do not place real orders or modify the exchange account during this implementation task. Use official Wallex API documentation and verify uncertain semantics with read-only probes or fixtures. Separate exchange facts from assumptions. Give concrete tests, actual command output, and remaining unknowns. Do not invent backtest performance or replace missing data with unlabelled synthetic results. Preserve a single decision/risk path across modes. Runtime AI must affect decisions; AI-written code alone does not satisfy that objective.

## Task 1 — exchange adapter and execution recovery

> Implement a typed exchange adapter and broker interface for replay, shadow and future live modes. Cover account routing, balances, actual fees, metadata, exact pair eligibility, candles, books, orders, fills, cancellation and reconciliation. Credit-account trading requires the account key plus `sub-account-client-id`; verify discovery and header behavior before enabling authenticated calls. Persist client IDs before submission; reconcile ambiguous timeouts before retries. Use decimal amounts and correct fee assets. Build an order state machine and a single-writer guard. Honor endpoint-specific rate limits. Verify tick/step metadata semantics and order-type support instead of guessing. Add meaningful fixtures for timeout-after-acceptance, cancellation racing a partial fill, restart recovery, self-cross prevention, and prohibited pairs. Deliver interface documentation and a read-only preflight command. Acceptance: offline tests pass, no duplicate exposure in failure simulations, and live order submission is disabled by default.

## Task 2 — data, learned strategy, and honest backtesting

> Implement a Wallex candle collector and a small preregistered momentum baseline with a learned expected-return filter. Prefer completed 15-minute candles initially. Check actual historical coverage; aggregate supported finer candles only when needed. Point-in-time features must use only information available before the decision. Backtest after estimated entry/exit fees, spread/impact, slippage and applicable financing. Use chronological walk-forward evaluation, purge overlapping forward labels, and fit preprocessing/calibration only in training windows. Save the dataset/config/model hashes and every experiment. Compare cash, the rule baseline, and the AI-filtered policy; show trade counts, net expectancy, P&L, drawdown and sensitivity. Do not imply that candle backtesting measures order-book queue fills. Acceptance: rerunning a fixed experiment reproduces its output, cost stress and leakage checks are included, and the report states whether an edge is supported, unsupported, or inconclusive.

## Task 3 — bounded runtime decision agent and risk engine

> Implement one autonomous decision agent with read-only tools for eligible market summaries, model scores, measured costs, portfolio state and recorded diagnostics. Return a strict structured choice among eligible candidates or abstain, with reason and expiration. Keep credentials and direct order submission outside its tool access. Its decisions must actually gate entries and be logged alongside predictor-only shadow decisions. A separate deterministic risk engine enforces position/exposure caps, cost hurdle, equity loss/drawdown stops, stale data checks, and end-of-event scheduling. On AI timeout or invalid output, block entries while preserving exits and recovery. Store model/prompt versions, tool inputs/results and raw structured outputs for replay. Acceptance: demonstrate a recorded AI decision changing an entry, a prohibited proposal vetoed by risk, model outage behavior, and exact replay from saved outputs. Label historical predictor-only tests accurately.

## Task 4 — integration, shadow testing, and submission evidence

> Integrate the agreed interfaces into one executable application with replay/shadow modes and a disabled-by-default live mode. Add a timezone-aware mandatory challenge deadline, startup reconciliation, continuous equity/drawdown accounting, machine-readable status and a compact terminal report. Run shadow and fault scenarios without real orders. Generate separate backtest/shadow/live reports; do not mix simulated fills with exchange fills. Add a manifest linking every deployed interval to commit/config/model/prompt versions. Provide reproducible setup, report and replay commands. Build the final technical Markdown document and a five-minute video script. Acceptance: a fresh environment can reproduce the recorded decisions/report, all gate failures remain visible, and secrets are absent from files intended for submission.

## Integration sequence

Agree on interfaces first: `MarketSnapshot`, `FeatureSnapshot`, `CandidateScore`, `AgentDecision`, `RiskDecision`, `OrderIntent`, `OrderUpdate`, `Fill`, and `PortfolioState`. Specify units, timestamps, Decimal serialization, schema versions, and identifiers.

Then land adapter/recovery and data/baseline work; add the runtime agent and risk engine; finally integrate shadow testing and evidence. Ownership can be assigned between Codex and Antigravity after existing repository contents and the remaining schedule are known. The integration owner reviews every change before merging.
